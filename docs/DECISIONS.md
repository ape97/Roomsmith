# Decisions

Architecture decision records. Status: `accepted` unless noted. New decisions get the next number; superseded ones are marked, not deleted.

| # | Decision | Reason | Consequences |
|---|---|---|---|
| 1 | App name "Roomsmith"; the entire UI, code, docs and repo are English | The repository is meant to become public | No localisation work in the first versions; strings kept in one place so localisation can be added later |
| 2 | Independent implementation: no code, models, textures, icons or text taken from other projects | Roomsmith stays MIT and independent of third-party licences | Own catalog designs and own implementation; see [LICENSE_REVIEW.md](LICENSE_REVIEW.md) |
| 3 | Own project format: package folder `Name.roomsmith/` with `project.md`, `assets/`, `backups/`. `project.md` is Markdown with YAML front matter and sections of tables and bullets | Fast to read and diff, readable by AI agents and humans, exact roundtrip | Needs a dedicated codec with roundtrip tests; format documented in [FILE_FORMAT.md](FILE_FORMAT.md) |
| 4 | No import or export of file formats of other planning programs | The project keeps its own format and does not build on third-party formats | No migration path from other programs |
| 5 | No third-party agent skill or plugin packages are required | Installing them would change global agent configuration | No third-party skill dependency; agent rules live in [AGENT_GUIDE.md](AGENT_GUIDE.md) |
| 6 | Platform macOS 26+, Apple Silicon; SwiftUI shell + AppKit for the 2D plan (`NSView`) + RealityKit `ARView` as a non-AR 3D view | Native look and performance; precise pointer input needs AppKit; RealityKit is Apple's supported engine (SceneKit is deprecated) | No older macOS or Intel support; gizmo and picking are built on top of RealityKit |
| 7 | Document units are integer millimetres (`Int64`); axes X east, Y north, Z up; RealityKit mapping x = X/1000, y = Z/1000, z = -Y/1000; one rounding rule (half away from zero); angles in degrees normalised to [0, 360) with 0.001 degree resolution | Exactness is a data property; one central transform avoids axis bugs | All conversions go through one module; free geometry uses `Double` with robust predicates and makes no exactness claim |
| 8 | Command engine with revisions drives undo/redo. UI and agents use the same commands. Objects a human is dragging are `BUSY` for agents; `expectedRevision` mismatch returns `CONFLICT` | Single validated mutation path; no silent overwrites | Every feature must be expressed as a command; drags commit one command on release |
| 9 | Publication: repository stays local, prepared in the style of public menu bar app repositories (README with icon, badges, GIFs, screenshots; MIT) | Public release must be a deliberate later step | No remote is created or implied; assets for the README are produced locally |
| 10 | Package layout: `RoomsmithCore` (no UI frameworks), `RoomsmithIPC`, `Roomsmith` (app), `roomsmith-mcp`, tests | Keeps model, geometry, commands and agent API testable without a GUI | UI-only logic must stay thin |
| 11 | Agent transport: MCP over stdio in `roomsmith-mcp`, bridged to the running app by a Unix domain socket with a token (newline-delimited JSON) | Local only, no network exposure, works with any MCP client, no model-specific code | Token storage and socket permissions must be tested; no shell or file tools are exposed |
| 12 | No third-party Swift packages; Apple frameworks only | Small supply-chain surface, simple licensing | Parsers, codecs and triangulation are written in-house and tested |
| 13 | 3D model import supports USDZ first | Natively supported by RealityKit, no extra dependency | Other formats (glTF, OBJ import) are backlog items |
| 14 | Furniture definition (reusable design) is separate from furniture instance (placed exemplar); instances reference definitions and hold state, pose and overrides | Product data and catalog entries exist without placement; edits to a definition propagate | Resolver combines definition, state and instance into world geometry |
| 15 | Per-state and per-configuration data are stored explicitly (poses per component or member), transitions are derived and never alter stored end transforms | Exact end states, safe undo and roundtrip | Animation is presentation only |
| 16 | Documentation GIFs and screenshots are produced with local tools (ffmpeg for GIFs); these tools are not shipped | Public README needs media | Media live in `docs/images/` and are tracked; they are rendered by the app itself from a generated demo project (`scripts/make-media.py` for the 3D pictures and GIFs, test hooks for window pictures), never recorded from the user's screen |
| 17 | Several projects are open at once as tabs of one window, each with its own store and undo history; tabs, the compare split and walk settings are app state and not part of any project file. Furniture moves between projects as a packed transfer (design, materials, product data, asset bytes), one undo step per side | A project file stays self-contained and a closed window leaves no workspace data inside it; undo of one project must not touch another | Moving is copy then delete, so a failed delete leaves the copy and reports it; the target needs a saved package when assets travel |
| 18 | Sun and sky settings (`lighting`) and the lamps of a furniture design are part of the project and undoable; walk settings are per user | The look of a scene belongs to the project and travels with it; how someone walks (speed, head bob) is a personal preference | The format has new optional keys and columns ([FILE_FORMAT.md](FILE_FORMAT.md)); older files read with defaults; walk settings are not shared between machines |
| 19 | The furniture library is global and separate from projects (`library.json`, entries, photos, thumbnails in the support folder); placing an entry copies it into the project with fresh ids | One collection of own designs for all projects; a project does not depend on the library after placing | A wholly damaged or newer index is moved aside and never overwritten; an index with damaged single items keeps the readable ones, is copied to `library.json.broken-<n>` before anything is saved, and a warning is reported; library tools change global data, so agents need write access |
| 20 | Furniture from photos runs on this Mac with the Vision framework and maps the result onto the five builder templates; nothing is uploaded | Privacy, no model dependency, and the result stays editable in the builder | An approximation, not a reconstruction; sizes must be given at least in one dimension; see "Known limits" in [STATUS.md](STATUS.md) |
| 21 | Lamps are RealityKit lights with a brightness factor chosen by eye, at most 8 shine at once, they cast no shadows, and OBJ and USDZ export carry no lamps or sun | RealityKit point lights cannot cast shadows and every light costs frame time | Lamp scenes are a visual aid, not a lighting simulation |
| 22 | Material presets and procedural patterns are generated in code (no bundled image files); a material stores the preset, pattern and its parameters | Patterns are rendered from their parameters (`ProceduralTexture.render`), so no image files are bundled and equal parameters give equal pixels | Patterns are generated per material in `Geometry/ProceduralTexture.swift` |
| 23 | Free camera: a fourth camera mode `free` where `target` is the eye (like first person), flown with W A S D / Q E, without collision or floor; in first person the gizmo, selection tint and hover tint are off | A fly camera makes it easy to look at furniture from any height while still editing; in first person the gizmo and tint could not be used and only distracted | Schema 3 → 4 (additive, stamp only); the mode is stored in the project camera and saved views; switching rules in `docs/DEVELOPMENT.md`; first-person clicks select nothing |
| 24 | My Furniture categories are user-made groups stored additively in `library.json` (optional `categories`, optional `categoryId` per entry; the format version stays 1). A dangling `categoryId` counts as Unsorted. Standard pieces stay a separate, read-only placeholder section and are copied into My Furniture on request | Collapsible groups were requested; old libraries and older app versions must keep working; the built-in catalog is not user data | Category names are unique ignoring case; deleting a category never deletes entries; the library has no Add button, entries come in through "Save to My Furniture" |
| 25 | Identical furniture designs are reused, not duplicated: a design equal to an existing own one except for ids (`FurnitureDefinition.isSameDesign`) is reused on paste/place and by `furniture.create_definition` (unless an `id` or `forceNew` is given); designs linked to a product are never merged. The "In this project" list folds same-named designs into one row; nothing is deleted automatically, clean-up is an explicit command (`Remove Unused Furniture…`, `furniture.prune_unused_definitions`, dry run by default) | Every model swap and every paste piled up unused designs (65 designs, 36 used in one project); silent deletion would surprise the user, hiding alone would leave the clutter | Strict equality keeps reuse safe but misses near-identical copies (the list rule and the clean-up cover those); a model swap should use `furniture.replace_definition` |
